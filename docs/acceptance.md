# Acceptance

Hand-run checks for the suite. An item is `N. **Title.** Setup: ... Command: ... Expected: ... Covers R.... Rerun when ...`, followed by its last result: `Last run <date> at <plugin version or commit>, <how it ran>: <passed, passed in part or failed>; <what the run showed>`, in one sentence. An item expects nothing its requirements, decisions or the text under test rule out, and nothing its Setup cannot produce. A new run replaces the result; the pull request that carries it says what else the run showed. An item not yet run says "Not yet run." Item numbers are never reused, and 18, 19, 20, 23, 26 and 50 are not in use. Runs use scratch profiles (`CLAUDE_CONFIG_DIR` outside the repository) and throwaway repositories. A new result names the permission mode of its run (requirement 275). An item that expects a reading block or a permission statement to print runs interactively, since a headless session does not reliably print them (decision 155); a headless run of such an item checks the rest and says so.
