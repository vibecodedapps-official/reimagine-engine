# Draft

Run this check on the finished text of a message to someone else, before the draft is first shown. Run it yourself and launch no agent for it, since verifying needs what this session did. The check strikes and verifies. It never adds detail.

## Strike

- A commit id, build number, file name, test id, count or explanation of a mechanism that no named reader acts on.
- A decision handed to the reader that is the sender's to settle. That includes an invitation to reverse or approve again what the sender already did, and a stated plan to go on doing what the message already shows.
- A sentence that restates a source the draft names.

## Verify

- Each statement the sender has not checked. Settle the ones within your reach and list the rest beside the draft. A draft never asks its reader to verify what the sender can.
- A statement that something was not done or not covered is a claim about state. Check it against the record.
- Read a name or an example again at its source, as you would a location.
- In a copy shown for pasting, an id is linked at first mention where its base is verified.
- A statement about another draft, a post or a check is true at the moment of sending. Read it again when either side changes. A summary whose verdict rests on checks still running waits for them.
- What another person will do is written as asked, never as agreed, unless they agreed.

## Notes for the owner

Notes stay outside the draft: what was left out and why, what could not be verified, and which sentence to check before sending. A doubt in the notes excuses no sentence of the draft that states it as fact.

## Email

An email draft is one HTML file in the scratch directory the house rules name, ready to open in a browser and paste, with its links and tables. It is the only stored copy, and the reply shows the draft as text taken from that file. Every other draft is Markdown. No draft is kept in two formats.
