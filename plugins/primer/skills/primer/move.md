# Move

A move takes a repository's tracked agent files out. What they hold is restated in the store, and one commit removes them, a tracked settings file among them: the only write and the only commit the run makes in the work tree. The run ends with the repository `local`, so its profile line is `primer: profile local`, and `local.md` governs every write to the store.

1. State the mode. Stop with nothing written when a tracked agent file has an uncommitted change. When git tracks no agent file there is nothing to remove: where the store holds the repository's layer and the map has no `local` entry for it, a move stopped after its commit, so go to the `map` command of step 6; else stop.
2. Inventory the agent files git tracks: the ones the `info/exclude` lines of `local.md` name, at any depth. A file that code, CI, a manifest or another tool reads, such as an `AGENTS.md` other tools load, is listed apart and stays until the user says.
3. Place what each file holds by the local profile section of `placement.md`:
   - A hub line, an unscoped rule and a nested file's text become statements of the group layer, restated as facts, since a layer holds no commands. A path-scoped rule becomes a document under the store, with a pointer that names the files it covers.
   - A skill moves to the store's `skills/` whole.
   - A setting, a permission, a hook, an MCP server and an agent definition are the host's configuration, which primer never writes: list each with the file of the user's own it would go to, and what stops when the tracked file leaves.
   - Text the code states, stale text and text true of every project is dropped, each with its reason.
4. Work out the `attribution` setting the removal commit would run under, with the tracked settings file the session started with and without it, from the settings files that then apply. Unless its `commit` and `pr` values are empty both ways, propose them by placement item 2, in a file of the user's own that wins over the tracked one, and make no removal commit until the user has set them or says the trailer may stay: the message would carry what the profile hides.
5. Print the plan and ask once: each store write, a layer with its `measure` output, the links, each configuration item of step 3, the removal commit with its branch, its subject and every file it removes, and the `map` command. It says that the commit removes the files for everyone who pulls it, and that they are back on any branch that lacks it.
6. On the yes, in this order, stopping at the first step that fails: write the store's files and read each back; make the links; make the removal commit; run the `map` command, `map --add --profile local`, or `map --set --profile local` where an entry exists; check that `status` gives each layer written with its canary.
7. The removal commit is `git rm` of the files the plan lists for removal and a commit of those paths alone. Its subject follows the repository's convention, else `chore: <subject>`. The message says which files leave and, at most, that the repository reads none of them: nothing the run writes in the subject or the body names a model, an agent, a tool, a plugin or a file named for one, or says where the text went, who keeps it or that it is still used, and the message has no `Instruction-file` line. Read the message back: where the host added a trailer the user did not allow, stop and say so, since the commit is unpushed and the user's to amend. Never push it: a push or a pull request is the user's to ask for, and a pull request's title and body hold to the same.
8. End with the store files written, the commit, each configuration item left to the user, and the `info/exclude` offer of `local.md`. Where the run stopped part way, say which steps are done; a second `/primer move` finishes it.
